## Запросы коллекции

Объект: учебный API Restful-Booker, https://restful-booker.herokuapp.com

| № | Запрос | Метод и путь | Что проверяет | Проверки |
|---|---|---|---|---|
| 01 | ping | GET /ping | Доступность сервиса | Код 200 или 201, время < 1500 мс |
| 02 | auth | POST /auth | Получение токена, сохраняет `token` в окружение | Статус 200, токен — непустая строка |
| 03 | booking: список id | GET /booking | Список идентификаторов бронирований | Статус 200, непустой массив, время |
| 04 | booking: создание | POST /booking | Создание записи, сохраняет `bookingId` | Статус 200, `bookingid` — число, имя совпадает |
| 05 | booking: проверка данных | GET /booking/{id} | Созданная запись читается корректно | Статус 200, имя, фамилия и цена совпадают |
| 06 | put | PUT /booking/{id} | Полное обновление (нужен токен) | Статус 200, цена обновилась |
| 07 | patch | PATCH /booking/{id} | Частичное обновление (нужен токен) | Статус 200, имя изменилось, остальные поля не тронуты |
| 08 | delete без токена | DELETE /booking/{id} | Запрет удаления без авторизации | Статус 403, время |
| 09 | delete | DELETE /booking/{id} | Удаление с токеном | Статус 201, время |
| 10 | несуществующий id | GET /booking/999999999 | Запрос несуществующей записи | Статус 404, время |
| 11 | auth неверный пароль | POST /auth | Вход с неверным паролем | Фиксирует поведение из BUG-006: 200, токена нет, `reason` |
| 12 | создание некорр данные | POST /booking | Создание без обязательного поля `lastname` | Код 4xx или 5xx, в ответе нет `bookingid` |

## Как запустить

1. Импортируй `Restful-Booker.postman_collection.json` и `RB-prod.postman_environment.json` в Postman.
2. Выбери окружение **RB-prod** (справа вверху).
3. Collection Runner, запуск всей коллекции по порядку.

Данные на стенде сбрасываются каждые 10 минут, поэтому если запись «пропала», создай её заново запросом 04.

## Найденные баги

BUG-006
Заголовок:
POST /auth: неверные учётные данные возвращают 200 OK вместо кода ошибки
Окружение: Postman 12.25, macOS 15.7.7, https://restful-booker.herokuapp.com
Шаги:
1. Создать запрос POST https://restful-booker.herokuapp.com/auth
2. Заголовок Content-Type: application/json
3. Тело: { "username": "admin", "password": "111password123456" }
4. Нажать Send
Ожидаемый результат:
Код ошибки аутентификации (401), в теле нет токена.
Фактический результат:
200 OK, тело {"reason": "Bad credentials"}. Токен не выдан.
Для сравнения: с верными данными 200 и поле token.
Severity:
Minor: доступ не получен, но статус не отражает провал авторизации
Priority:
Low: клиенты могут обойти это проверкой тела, сервис работает
Воспроизводимость: 3 из 3
